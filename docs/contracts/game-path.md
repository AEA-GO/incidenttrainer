# Contract 5: game path and game cookie

Version: **v0.1 (draft)**. Changes freely until v1; after v1, only through an ADR.

Everything a player does during a game goes through one path, `/s/<game_id>/...`, on our one domain.
CloudFront sends it to the **gateway** (nginx + gateway-auth), which checks the **game cookie** and forwards to the player's own game server.
The API issues the cookie (contract 3); the agent behind it is contract 2.

## Paths

| Browser path | Forwarded to | Path on the server | Notes |
| --- | --- | --- | --- |
| `/s/<id>/api/v1/<rest>` | agent `:8080` | `/v1/<rest>` | JSON. While the game is `booting`, gateway-auth answers `GET .../api/v1/state` itself (below) |
| `/s/<id>/grafana/<rest>` | Grafana `:3000` | unchanged (`/s/<id>/grafana/<rest>`) | Grafana is started with this sub-path at claim time |
| `/s/<id>/term/` `.../term/token` `.../term/ws` | ttyd `:7681` | `/`, `/token`, `/ws` | only for labs with a terminal, from `ready` on; WebSocket on `/ws` |
| anything else under `/s/<id>/` | none | | `404 not_found` |

- `<id>` is the game id: 22 characters `[A-Za-z0-9_-]` (128 random bits).
- Port 8081 (agent control) is **never** reachable through these paths.
- The gateway takes the server address **only** from DynamoDB, never from the request, and refuses any address outside the sandbox subnet (`10.20.0.0/20`).

**Why Grafana keeps the full path:** Grafana builds its links from `root_url`, so it must know the exact sub-path. The game id is only known at claim time, so the agent starts Grafana then with `GF_SERVER_ROOT_URL=<public_base_url>/s/<id>/grafana/` and `GF_SERVER_SERVE_FROM_SUB_PATH=true` (contract 2, `claim`). Other Grafana settings are baked into the image: anonymous access as Viewer, embedding allowed, dark theme, Explore allowed for viewers, no login form.

**Why the terminal path is stripped:** our own xterm.js client talks to ttyd directly (`GET token`, then a WebSocket on `ws` with subprotocol `tty`), so ttyd needs no per-game setting. ttyd runs with `-W` (writable), `-m 2` (a reload can reconnect), `-P 30` (ping), as user `oncall` with passwordless sudo. The agent starts it only for labs with `terminal: true`.

## The cookie

| Part | Value |
| --- | --- |
| Name | `__Secure-itr_game` |
| Value | `v1.<game_id>.<exp>.<kid>.<sig>` |
| `exp` | Unix seconds; issue time + 2700 (45 min, the server's lifetime) |
| `kid` | id of the signing key, `^k[0-9]{1,6}$` |
| `sig` | base64url without padding of HMAC-SHA256(key, ASCII `v1.<game_id>.<exp>.<kid>`): 43 characters |
| Attributes | `Path=/s/<game_id>/; Max-Age=2700; Secure; HttpOnly; SameSite=Strict` (no `Domain`) |

- Set by `POST /api/sessions` (contract 3). Because the path is per game, several games in several tabs don't clash.
- `HttpOnly`: website JavaScript never reads it. `SameSite=Strict` plus the JSON-only rule in contract 2 blocks cross-site requests.
- The `__Secure-` prefix makes browsers refuse it over plain HTTP. (`__Host-` would need `Path=/`, which we don't want.)
- No personal data inside: just the game id and expiry.

### Keys

- Stored in DynamoDB, item `CONFIG / COOKIE_KEYS` (data-model.md): `{current: "k2", keys: {"k1": {secret, created_at}, "k2": {...}}}`; each secret is 32 random bytes, base64url.
- DynamoDB, not SSM: the gateway has no internet and only S3/DynamoDB endpoints, and an SSM endpoint would cost ~$7/month.
- The API signs with `current`; gateway-auth accepts any key in `keys`. Both cache the item for 5 minutes.
- **Rotation** (script, by hand): add a new key, wait 5 minutes, make it `current`, wait 50 minutes (longer than any cookie), remove the old one. Rotate when a teammate with table access leaves, or yearly.
- Generated by a script with `secrets.token_bytes(32)`, never by Terraform (it would land in the state file).
- Anyone who can read the table (the API, the gateway, the team's read-only role) can read the keys. Acceptable: a forged cookie only opens a game server, which holds nothing worth stealing.

### Checking a cookie (gateway-auth, every request)

1. The path matches `^/s/([A-Za-z0-9_-]{22})/(api/v1/|grafana/|term/)`, else `404 not_found`.
2. The cookie is present and splits into exactly 5 parts with `v1` first, else `401 bad_cookie`.
3. `kid` is known, and `sig` equals the recomputed signature, compared in **constant time** (`hmac.compare_digest`), else `401 bad_cookie`.
4. `exp` is in the future, else `401 expired`.
5. The cookie's game id equals the path's game id, else `403 wrong_game`.
6. The game exists in DynamoDB (`GAME#<id> / META`, cached 60 s), else `404 not_found`.
7. Routing by state, below.
8. Answer nginx `200` with `X-Itr-Upstream: <private ip>` (nginx picks the port from the path); record the heartbeat.

## Routing by game state

| Game state | `GET .../api/v1/state` | Other agent paths | Grafana | Terminal |
| --- | --- | --- | --- | --- |
| `booting` | answered by gateway-auth: `200 {"state": "booting", "boot": {...}}` and it tries the next broker step (below) | `503 booting` (`Retry-After: 2`) | `503 booting` | `503 booting` |
| `ready` … `watching` | agent | agent | Grafana | ttyd (labs with a terminal), else `404 no_terminal` |
| `ended`, server still running | agent (shows the end) | agent (it refuses changes) | Grafana | closed: `410 ended` |
| `ended`, server gone | `410 ended` | `410 ended` | `410 ended` | `410 ended` |

`boot` contains the same progress as `GET /control/v1/ready` (`components`), so the boot screen needs only this one URL.

## gateway-auth as broker

A background loop (every 5 s) goes through the games in `ACTIVE` (data-model.md). Browser polls of `/state` for a booting game trigger the same step immediately, so the boot is fast when the player watches and still finishes when they don't.

| Game | What gateway-auth does |
| --- | --- |
| `booting` | `GET /control/v1/ready` until `booted`; then make the control token (32 random bytes) and save it on META with a condition (`attribute_not_exists(control_token)`, so two workers can't both claim); `POST /control/v1/claim`; read `labs/<lab>/v<version>/runbook.json` from S3; `PUT /control/v1/runbook`; write `agent_ready` and set state `ready` |
| `ready` … `watching` | every ~10 s `GET /control/v1/report?after_seq=<saved>`; write new events to DynamoDB; copy `state`, `severity`, `reopened` onto META |
| idle: no request for 300 s | write `heartbeat_lost`; `POST /control/v1/end`; continue as below |
| agent says `ended` | copy the remaining events; **then** set META state `ended` (with the condition `state <> ended`); remove from `ACTIVE`; decrement the running counter |
| agent unreachable for 60 s | write `ended` (reason `abandoned`, final health = last `health` event) itself; the cleanup Lambda deletes the server |

Because META becomes `ended` only after the final events are saved, `POST /api/sessions/{id}/finish` (contract 3) can safely score as soon as it sees `ended`; until then it answers `409 not_ended` and the website retries after a couple of seconds.

**Heartbeat:** any authorised request updates `last_seen_at` on META, at most once per 30 s per game (a conditional update keeps writes cheap).

## Headers

To the server (set by nginx, overwriting anything the browser sent):

| Header | Value |
| --- | --- |
| `X-Itr-Game-Id` | the checked game id |
| `X-Request-Id` | nginx `$request_id`, also logged by gateway-auth and the agent |
| `Cookie`, `Authorization` | removed |
| `X-Itr-Upstream` and any other `X-Itr-*` from the browser | removed before `auth_request` |

Back to the browser: `Cache-Control: no-store` on agent responses. CloudFront adds the security headers policy (`X-Frame-Options: SAMEORIGIN`, so our own page may frame Grafana and nobody else can).

**WebSocket origin check:** for `.../term/ws`, gateway-auth also requires `Origin` to equal our public origin (`403 bad_origin`), against cross-site WebSocket hijacking.

## Limits at the gateway

| What | Limit |
| --- | --- |
| Agent paths | 10 requests/s per game, burst 20; body ≤ 64 KB; read timeout 35 s |
| Grafana | 50 requests/s per game, burst 200 (a dashboard loads many panels); body ≤ 1 MB; read timeout 60 s |
| Terminal | 2 open WebSockets per game; idle timeout 1 h; input frames ≤ 64 KB |
| Over a limit | `429 too_fast` with `Retry-After` |

## CloudFront behaviour `/s/*`

- Origin: the gateway through a **VPC origin** (HTTP 80 inside the VPC; no public IP). Free; WebSockets supported.
- Cache policy `CachingDisabled`; origin request policy `AllViewer` (cookies, query strings, headers incl. WebSocket upgrade).
- Allowed methods: all; origin read timeout 60 s; compression on; same security headers policy as the site.
- Cost: none beyond normal CloudFront requests.

## Errors from the gateway

Same JSON shape as contracts 2 and 3: `{"error": {"code", "message", "retry_after_s"?}}`.

| Status | Code | When |
| --- | --- | --- |
| 401 | `bad_cookie`, `expired` | cookie missing, forged or old |
| 403 | `wrong_game`, `bad_origin` | cookie for another game; WebSocket from another site |
| 404 | `not_found`, `no_terminal` | unknown game or path; lab without a terminal |
| 410 | `ended` | the game is over and the server is gone |
| 429 | `too_fast` | rate limit |
| 502 | `server_unreachable` | the game server didn't answer |
| 503 | `booting` | still starting (`Retry-After: 2`) |

## On a laptop

The same paths work locally: `docker compose` runs nginx + gateway-auth next to the shop, cookie keys come from the environment variable `ITR_COOKIE_KEYS` (same JSON as the DynamoDB item), and the "server address" is the local shop. Chrome and Firefox accept `Secure` cookies on `http://localhost`; if a browser refuses, `ITR_COOKIE_INSECURE=1` (laptop only) drops the `__Secure-` prefix and the `Secure` flag.

## Changes to this contract

Adding a path or a header: minor version. Changing the cookie format: bump the value prefix to `v2`; the gateway accepts `v1` and `v2` for one hour while both exist.
